/******************************************************************************
** Task: Improving quicksort
**
** 2. Do the following changes affect the complexity
**    of quicksort on any of the three degrees of sortedness of the input?
**    If so, what is it that changes?
******************************************************************************/

Shuffling the array first:
Yes. It does not really change quicksort’s worst-case big-O, but it does change how it behaves on sorted or nearly sorted input. If I shuffle the array first, quicksort is less likely to keep picking bad pivots from an already ordered list, so it usually works much better.

Median-of-three pivot selection:
Yes. This helps mostly on sorted or nearly sorted input because the pivot is chosen from the first, middle, and last elements instead of always using the first one. That usually gives a more balanced split, so quicksort does not get stuck with the very uneven recursion that makes it slow on ordered data. On random input, the big-O stays the same, but the runtime can still improve a bit.

Insertion sort for small subarrays:
No, not in the asymptotic sense. Quicksort still has linearithmic behaviour for large inputs, but small subarrays are faster with insertion sort because it has less overhead on tiny arrays. So this mainly helps the actual runtime, not the big-O.

/******************************************************************************
** 3. What is a good cutoff to use for insertion sort?
**    Explain briefly how you came to this answer.
**    Remember that you should try to find the answer in a systematic way.
******************************************************************************/

I found that a cutoff of about 49 works well. I tested several nearby values with the optimised quicksort setup already enabled, and 49 gave the best runtime in my runs. It seemed like a good balance because insertion sort is faster on small subarrays, but if the cutoff gets too large, quicksort spends too much time on insertion sort instead of partitioning.

/******************************************************************************
** 4. Which combination of improvements gives the best performance?
******************************************************************************/

The best performance came from using all three improvements together: shuffling first, using median-of-three pivot selection, and switching to insertion sort for small subarrays. For me, that combination gave the most reliable and fastest result because shuffling avoids bad input order, median-of-three helps choose a better pivot, and insertion sort cuts down the extra recursion on tiny subarrays.
