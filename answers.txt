/******************************************************************************
** Task: Improving quicksort
**
** 2. Do the following changes affect the complexity
**    of quicksort on any of the three degrees of sortedness of the input?
**    If so, what is it that changes?
******************************************************************************/

Shuffling the array first:
Yes. It does not change the worst-case big-O of quicksort itself, but it changes how the algorithm behaves on sorted or nearly sorted input. By randomizing the array first, quicksort avoids always picking a bad pivot from an already ordered array, so the performance on sorted input becomes like the random case instead of collapsing into a bad case.

Median-of-three pivot selection:
Yes. This mainly helps on sorted or nearly sorted input because the pivot is chosen from the first, middle, and last elements instead of always taking the first one. That usually gives a more balanced split, so quicksort avoids the very unbalanced recursion that causes slow performance on sorted data. On random input, the complexity stays roughly the same, but the constant factor can improve.

Insertion sort for small subarrays:
No, not in the asymptotic sense. Quicksort still has linearithmic behaviour for large inputs, but small subarrays are handled faster because insertion sort has less overhead on tiny arrays. So this mainly improves the practical running time, not the big-O complexity.

I found that a cutoff of about 49 works well. I tested several nearby values with the optimised quicksort setup already enabled, and 49 gave the best runtime in my runs. It seems to be a good balance because insertion sort is faster on small subarrays, but if the cutoff gets too large, quicksort starts doing too much insertion sort work instead of partitioning.

/******************************************************************************
** 4. Which combination of improvements gives the best performance?
******************************************************************************/

The best performance came from using all three improvements together: shuffling first, using median-of-three pivot selection, and switching to insertion sort for small subarrays. Shuffling protects quicksort from bad input order, median-of-three helps choose a better pivot, and insertion sort removes extra recursion on tiny subarrays.
